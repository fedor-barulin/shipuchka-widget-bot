# Telegram widget bot: шаблон для HTMLBubbles

Минимальный бот, который присылает HTML-виджет (HTMLBubbles): веб-страницу прямо внутри сообщения Telegram, без Mini App и хостинга. В комплекте пробник `widgets/probe.html`: он показывает, что умеет движок виджетов на вашем устройстве, и кнопкой спрашивает бота. Замените пробник своим HTML, а `answer_query()` в `bot.py` - своей логикой, и у вас своя игра, опрос или калькулятор в чате.

## Почему MTProto, а не Bot API

В публичном Bot API (10.3) метода для виджетов нет, 10.4 с `sendWidget` пока в бете. В протоколе MTProto виджеты есть с 233-го слоя, и бот ходит туда по своему токену через [Telethon](https://github.com/LonamiWebs/Telethon).

`tgwidget.py` описывает нужные типы руками и регистрирует их в Telethon. Схема взята из `api.tl` Telegram Desktop. Она отличается от документации [widget-sandbox](https://github.com/TelegramMessenger/widget-sandbox): там у `inputMediaWidget` другие флаги, а сервер принимает вариант из Desktop.

```
inputMediaWidget#44f6c04e flags:# allow_queries:flags.0?true shared_widget:flags.1?true
  width:int height:int html:string public_data:flags.2?string chat_data:flags.3?string = InputMedia;
updateBotWidgetQuery#b373fe68 ... data:bytes ... = Update;
messages.setBotWidgetQueryAnswer#f8cdec6a flags:# query_id:long result:flags.0?string = Bool;
```

- Отправка: `messages.sendMedia` с `InputMediaWidget(html)`.
- Виджет вызывает `TelegramWidget.request("...")`, бот получает `UpdateBotWidgetQuery` и отвечает `SetBotWidgetQueryAnswerRequest` в течение 15 секунд.

## Подмена слоя и чем она грозит

Telethon 1.45 работает на слое 229, а запросы из виджетов сервер шлёт только клиентам слоя 233. Поэтому `tgwidget.py` выставляет `telethon.client.telegrambaseclient.LAYER = 233`.

Цена: типы, которые изменились между 229 и 233, Telethon не разберёт, и бот упадёт. Два из них уже починены в `tgwidget.py`:

- `channel` - приходит, если бот стал админом канала (например, чтобы проверять подписку). Без парсера бот падает при каждом запуске.
- `messageReplyHeader` - приходит, когда отвечают на сообщение.

Изменились ещё `channelFull` и `userFull`, но бот их не запрашивает. Если упадёт на чём-то новом, в логе будет `TypeNotFoundError` с ID конструктора: найдите его в `api.tl` Telegram Desktop и допишите парсер по образцу `Channel233`. Всё, что не связано с виджетами (подписка, меню команд, описание бота), надёжнее делать через обычный Bot API тем же токеном: он от подмены слоя не зависит.

## Запуск

1. Создайте бота у @BotFather и возьмите токен.
2. Возьмите `api_id` и `api_hash` на my.telegram.org.
3. Скопируйте `.env.example` в `.env` и впишите значения.
4. `docker compose up -d --build`
5. Напишите боту `/start`.

Сервер нужен с доступом к Telegram: из России бот не подключится. Без Docker: `pip install -r requirements.txt`, выставить переменные из `.env` и `python bot.py`.

`watchdog.sh` раз в 2 минуты из cron проверяет контейнер и пишет в Telegram первому id из `ADMIN_IDS`, если бот упал, перезапускается по кругу или пишет ошибки, и ещё раз, когда он поднялся.

## Что умеет движок виджетов (проверено 06-07.11.2026)

- Виджет - один HTML до 32 КБ, в сжатом виде до 4 КБ. Без внешних картинок, шрифтов и запросов в сеть: только `data:` и встроенный SVG.
- Ширина = ширина пузыря: 430 px на десктопе, около 362 px на телефоне. Верстайте резиново, высоту задаёт `height` (до 600).
- Нет `vh`/`vmin` (высота 0). Есть flex, grid, `min()`, `clamp()`, SVG, CSS-анимации, `localStorage` (у каждого сообщения своё, до 4 КБ).
- Больше 500 мс непрерывного JS - «Виджет остановлен». Десятки таймеров или постоянный цикл анимации на JS роняют виджет. Рабочий вариант: CSS-анимации и разовые `setTimeout`.
- Один тап разблокирует один вызов: `request`, `openLink` или `openTelegramLink`. Без тапа - только в личке с ботом: при появлении и дальше раз в 5 секунд.
- Запрос до 64 байт, ответ до 1 КБ, на ответ 15 секунд.

## Куда виджет можно отправить (проверено 07.11.2026)

| Куда | Результат |
|---|---|
| Личка с ботом | работает |
| Пересылка из лички | нельзя: сервер ставит `noforwards` на каждый виджет |
| Инлайн-режим (@бот в другом чате) | `INPUT_MEDIA_WIDGET_NOT_ALLOWED` |
| Канал | `INPUT_MEDIA_WIDGET_NOT_ALLOWED` |
| Группа обсуждения канала | `INPUT_MEDIA_WIDGET_NOT_ALLOWED` |

Документация разрешает пересылку, инлайн и группы, но на бете сервер их закрыл. Делиться виджетом пока можно только ссылкой на бота.
